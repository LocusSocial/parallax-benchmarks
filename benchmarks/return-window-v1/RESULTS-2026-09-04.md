Date: 2026-09-04  
Status: reproducible case study, not a general model-quality claim

## Result

The same model started from the same implementation and visible tests. The supplied engineering
context was the intended experimental variable.

| Arm | Supplied authority | Model | Effort | Tokens | Wall time | Visible tests | Independent goal oracle |
| --- | --- | --- | --- | ---: | ---: | --- | --- |
| Spec-bound | Existing `SPEC.md` | `gpt-5.6-sol` | high | 28,954 | 149.0 s | PASS (8) | **0/5** |
| Goal-first | Original `BUSINESS_GOAL.md`; derived files treated as untrusted | `gpt-5.6-sol` | high | 19,042 | 161.3 s | PASS (9) | **5/5** |

Both arms began with implementation SHA-256
`f6cb78961a354f314aa03eff7585a4a18fd67c680197c1228c98f689987b05a4` and used
`codex-cli 0.153.0`. Each exited successfully.

The Spec-bound arm made its implementation and tests more consistent with the supplied Spec, but
failed every independent business requirement. The Goal-first arm restarted from the customer
promise, repaired the specification, implementation, and tests, then passed all five requirements.

## What this establishes

This run reproduces one concrete failure mode: downstream review can reinforce a plausible but
wrong specification. Starting from the original business goal can recover the intended outcome.

It does **not** establish a universal win rate, compare foundation-model quality, or prove that one
passing implementation is defect-free. The run was not token-budget matched; token usage is shown
instead of hidden. Stronger claims require repeated runs and a real Parallax multi-model arm under
equivalent limits.

## Reproduce

Verify the fixture first:

```sh
python3 scripts/verify.py
```

Then run each arm into a new output directory:

```sh
python3 scripts/run-codex-arm.py spec-bound results/<run-id>-spec-bound
python3 scripts/run-codex-arm.py goal-first results/<run-id>-goal-first
```

The runner saves the prompt, model and CLI version, reasoning effort, start and finish times,
before/after scores, source hashes, final message, edited workspace, and full transcript.
