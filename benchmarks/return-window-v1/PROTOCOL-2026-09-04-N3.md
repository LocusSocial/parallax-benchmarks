# Confirmatory repetition protocol — 2026-09-04 N=3

Frozen after the exploratory `r1` pair and before running repetitions `r2`–`r4`.

## Question

In this fixture, does supplying the original business goal and explicitly treating derived
artifacts as untrusted reliably change whether the final implementation satisfies the independent
business-goal oracle?

## Fixed design

- Three new valid runs per arm; six valid runs total.
- Arm order is counterbalanced:
  - pair `r2`: Spec-bound, then Goal-first;
  - pair `r3`: Goal-first, then Spec-bound;
  - pair `r4`: Spec-bound, then Goal-first.
- Model: `gpt-5.6-sol`.
- Reasoning effort: `high`.
- CLI configuration: ephemeral, user config ignored, repository rules ignored.
- Starting implementation SHA-256:
  `f6cb78961a354f314aa03eff7585a4a18fd67c680197c1228c98f689987b05a4`.
- Frozen prompts: `prompts/spec-bound-review.md` and `prompts/goal-first-single.md`.
- No token or wall-time cap. Actual tokens and duration are reported for every run; the two arms
  are not described as budget-matched.
- Primary outcome: number of the five independent business requirements passing.
- Secondary outcome: visible test-suite exit code.

## Validity and stopping rule

A run is valid when the Codex process exits successfully and both before/after scorer records are
present. Infrastructure failures are retained, marked invalid, and rerun under a new attempt name;
they are not silently deleted. Stop after exactly three valid runs per arm.

All valid outcomes are included regardless of score. The exploratory `r1` pair is reported
separately and is not pooled into the confirmatory N=3 headline.

## Evidence boundary

This experiment tests one small known-answer fixture and one model/version family. It can show
repeatability for this failure mode. It cannot establish a universal quality improvement, isolate
multi-model benefits, or prove Parallax product superiority. The real Parallax arm remains a
separate product experiment.
